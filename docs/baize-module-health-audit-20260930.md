## 3. 关键调用链与断点

```text
浏览器 Cookie → /api/ai/assistant（身份、限流、安全）
  → PG 会话/近期消息/用户实体索引
  → 本地规则 或【当前进程不可用】DeepSeek 统一网关意图分类
  ├─ 业务查询 → Schema/角色 → /api/ai/business-records → PG 租户/assignment scope → 工具审计 → 回复/来源
  ├─ 知识问题 → PG RAG 检索/权限/引文 →【当前无文档】拒答；有文档时当前为提取式降级
  ├─ 明确 dispatch+skillId → 任务 Preview → 人工审批 → Skill Gateway → PG 业务效果/事件
  └─ MCP / 任意工作流 → 当前无对话自动调用路径；控制面另有独立 API
  → 输出复核 → 消息落 PG → JSON 或 SSE done；异步 outbox 交付未验证
```

最重要的行为断点是 `src/lib/ai/assistant/engine.ts:226`。在外部模型不可用的单域查询中，地点参数只来自模型分类，不来自用户原话的本地槽位提取；因此虽然读模型本身能正确过滤，“智能体答复”仍可能错误。应将**已解析条件与实际执行条件**留痕并做回归比较，不应仅看 200 状态码。

## 5. 问题与优先顺序

1. **P0（试点准入前）——自然语言筛选条件被忽略导致错误事实**：模型关闭时解析明确的“3号楼/本地集成楼栋 101”并传给只读工具，回复前比较执行参数和原输入，新增至少地点、时间、否定条件回归；禁止仅以 `200` 验收。
2. **P0（如需启用模型能力）——当前在线 DeepSeek 不可用**：使用服务器秘密管理注入有效密钥，校对租户模型路由、额度、审计与熔断，再做实际 30 轮多主题和并发 HTTP 流验收。不要把一次历史 live 探针当在线状态。
3. **P1——部署资源缺位**：由业务方审核并发布真实校园知识文档/工作流；运维注册可信 HTTPS MCP，做探测、只读调用、权限和审计。**当前三者都是 0**，但应用本身没有 5xx 故障。
4. **P1——对话工具边界不匹配宣传**：若要支持从自然语言直接挑选工作流/MCP，应另建注册、Schema、租户 scope、审批、审计的受控适配；目前白泽对话只直接用 PG 业务读工具、RAG 和显式 Skill 调度，不能将插件/MCP 控制面当作已接入对话。
5. **P1——outbox 交付闭环**：核实/实现部署中的消费者进程、重试与积压告警，并区分任务事件记录与实际通知送达。本隔离库 11 条 PENDING 中 7 条引用已清理的测试任务，应先按测试数据处理，不能直接推断校园生产积压。
6. **P1/P2——安全与体验验收**：真实角色集合、敏感内容评测、移动端/断流、长时压力；学生宿舍号须先确定可信人员—房间关联，不得推断或编造。

**最终判定：基础受控智能体可在隔离环境继续测试；“全工具自主管理与执行”的能力尚未完整可用；生产/真实校园上线仍为 NO-GO。**
